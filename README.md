# Infron 内容推荐 Skill
中文版 · v0.1.3

**你输入一句话，AI自己找内容，直接给你值得读、值得分享的帖子或文章网址。**

## 怎么用

在能读取本项目且具备搜索工具的AI中发送：

> 使用 Infron Repost Sourcing Skill，自己搜索并推荐2–3条最近值得读、值得分享的AI模型或推理工程内容。直接给我链接、内容重点和推荐理由，不需要报告。不发布内容。

如果AI没有自动发现项目Skill，可把第一句替换为：

> 读取 skills/infron_repost_sourcing/SKILL.md 并按默认流程执行。

你不用先找链接，不用填JSON，不用跑Python，也不用逐个阅读文件夹。

## 你会收到什么？

聊天里通常直接出现2–3条推荐，每条包含：

- 实际读过的帖子或文章链接、来源和日期。
- 内容解决什么问题、读者能学到什么。
- 为什么适合Infron的开发者受众，值得分享的切入点。

优先近期内容，但有价值的工程指南不会因为超过48小时就自动淘汰；旧内容要明确日期和当前用途。模型与工程题材尽量兼顾，不机械凑固定名额。某条X原帖读不到，就寻找并阅读作者的一手文章，或者换候选，推荐实际可读的网址，不编造X链接。

默认不生成独立报告，不返回Hold/deferred待办表。内部可以保存简短来源记录。遇到所有可用来源均无法读取等真实限制时仍需说明，不能保证每次非空而编造推荐。

## 按什么标准选？

| 标准 | 判断问题 |
| --- | --- |
| 开发者价值 | 能帮助模型选择、部署、性能、成本、可靠性或工程实践吗？ |
| 内容实质 | 有具体方法、证据、代码或有用经验吗？ |
| 时效与用途 | 为什么现在值得读，是否准确标注发布时间？ |
| 品牌适配 | 是技术知识，还是替业务重叠平台导流？ |
| 增量 | 与已有分享相比有没有新信息？ |

优先一手来源，实际读取核心内容；不只读搜索摘要，不按点赞阈值，也不虚构总分。你的最新要求和当前品牌背景优先于暂定规则。

## 为什么这版改了默认流程？

前几版把“发现有价值内容”做成了“官号发布前审核”，所以原帖媒体打不开就卡住，还要求导出复杂记录。这与日常需求不一致。

v0.1.3默认是**选题/内容推荐**。推荐一个已经读过的一手文章，不需要先证明它对应的X帖子所有媒体都能访问；但不能把文章推荐说成原X帖子已完成转发审核。性能数字要有实际依据，不把作者报告写成独立复现。

如果你明确说“审核这条原帖能不能直接给官号repost/quote”，才进入原来的严格审核流程，检查必要媒体、品牌风险、时效、重复并按需输出审核报告。该流程仍可能暂缓，默认找内容时不强制执行它。

## 当前能力与边界

AI通过宿主搜索工具主动发现内容；独立X API后台采集尚未实现。不自动发布、购买、部署或启动定时任务。内容推荐不代表mentor认可或发布授权。

原离线审核程序及29项测试保留。代码测试不能证明推荐一定符合你的偏好，真正效果看实际聊天推荐与使用反馈。本版改的是默认任务和执行路径，而不是通过修改旧测试结果提高成绩。

本地独立版本位于outputs/Infron_Repost_v0_1_3；旧版本和原桌面项目保留。日常从本README的一句话开始即可。
