# Infron Repost Sourcing

中文版 · 当前 Skill：v0.2.0

这是一个供 Infron 同事复用的内容发现 Skill，帮助 AI 主动发现、阅读并推荐与 AI 基础设施有关的内容：X、LinkedIn 原帖，以及一手技术文章、论文、模型卡或仓库。输入一个主题，或让 AI 自行寻找近期机会；默认直接在聊天中给出推荐，不发布内容。

它解决的是“值得看、值得分享什么”的前置筛选问题，不是自动发帖器，也不是用标题、搜索摘要或点赞数批量打分的工具。AI 必须实际读取候选帖子的核心内容，再给出技术价值、Infron 关联和分享角度。

## 使用

### 1. 安装到工作项目

在 PowerShell 中从本仓库运行安装器。先用 `-WhatIf` 查看计划复制的文件：

```powershell
.\Install-To-Project.ps1 -ProjectRoot 'C:\path\to\your-project' -WhatIf
.\Install-To-Project.ps1 -ProjectRoot 'C:\path\to\your-project'
```

安装器会复制 `skills/infron_repost_sourcing/`，并在目标项目没有品牌上下文时补充精简版 `workflows/infron-content/02_Brand_Context.md`。目标项目已有同名文件时不会静默覆盖；Skill 文件内容不一致会在复制前停止。

### 2. 在聊天中调用

使用能读取工作区、联网搜索和读取社媒帖子的 AI 环境，从项目根目录引用：

> 读取 `skills/infron_repost_sourcing/SKILL.md`，帮 Infron 找关于【模型/功能/主题】值得 repost 的 X 或 LinkedIn 原帖。给出链接、内容重点、推荐理由和分享角度。

也可以不指定主题：

> 读取 `skills/infron_repost_sourcing/SKILL.md`，寻找近期与 Infron 业务相关的讨论，推荐 2–3 条值得分享的 X 或 LinkedIn 原帖。说明讨论依据和业务关联，不发布内容。

如果也希望推荐一手技术内容：

> 读取 `skills/infron_repost_sourcing/SKILL.md`，帮 Infron 找近期值得分享的推理工程内容；社媒原帖和已读的一手技术文章、论文或仓库都可以，请区分可直接 repost 的原帖和内容选题。

指定主题时，AI 应围绕该主题搜索，不要擅自换成无关热点；不指定主题时，AI 才进入“热点机会”发现路线。默认两类来源都可以推荐；如果明确只要社媒帖、某个平台或其他指定类型，AI 应遵守限制，不能用其他类型凑数。通常不需要先提供链接、填写 JSON 或运行 Python。当前 `skills/` 是手动引用入口，不保证被所有 VS Code 配置自动发现。

### 3. 推荐结果包括什么

正常交付在聊天中完成，不生成独立报告。每条推荐应包括：

- 来源类型和实际链接、作者或机构、平台或来源、日期；
- 这是“指定主题”还是“热点机会”，以及相应的主题或注意力依据；
- 帖子讲了什么，读者能学到什么；
- 为什么 Infron 有自然且可信的参与理由；
- 社媒原帖适合纯 repost 还是 quote/comment，以及建议的分享切入点；一手技术内容则标明建议分享的平台和选题角度，不冒称可直接 repost；
- 影响使用的重要证据或品牌不确定性。

通常目标是 2–3 条，但合格内容不足时应少给，不要用未读链接凑数。社媒原帖必须是实际读过的帖子链接；文章、论文和仓库要标明真实类型，不能伪装成可直接 repost 的原帖。

#### 示例格式

以下是**虚构示例**，用于展示格式，不代表真实来源或事实：

> **一手技术内容 · 文章**｜示例作者｜示例日期
>
> **内容重点**：文章介绍如何观察缓存对推理工作负载的影响。
>
> **为什么值得分享**：帮助开发者理解延迟与成本之间需要同时观察的指标。
>
> **Infron 角度**：X 可聚焦一个工程取舍；LinkedIn 可先解释工作负载问题，再说明读者如何判断。
>
> **使用边界**：这是内容选题，不是已确认存在的社媒原帖。

## 推荐标准与边界

- 必须实际阅读候选的核心内容；搜索摘要只能作线索。社媒原帖与一手技术内容分别标注，阅读受阻时替换候选，不编造链接或凑数。
- 比较开发者价值、技术内容、时效、品牌适配和信息增量。热点需要可观察的讨论或事件依据，不能仅因为发布时间近就称为热点。
- 不编造 Infron 的模型支持、功能、优惠或合作；对业务重叠产品的推广保持审慎。推荐不等于批准或发布授权。
- 原帖推广业务重叠产品时优先换帖；品牌关系有疑点时结合内容和任务判断，说明影响使用的重要不确定性，不把它当作发布批准。
- 通常推荐 2–3 条；合格内容不足时如实说明。宿主需要联网和可用的社媒阅读工具；本项目没有独立的 X/LinkedIn API 采集器。
- 只有明确要求检查特定原帖能否用于官号发布时，才使用更严格的审核流程。旧的离线审核工具仅支持 X，不可用来证明 LinkedIn 审核通过。

### 时间优先级

- 默认从**近 7 天**开始搜索；快速变化的新闻优先近 **48–72 小时**。
- 合适内容不足时可以扩展到 **14 天**；更早的内容需要明确说明为什么现在值得分享。
- 用户给出时间范围时，以用户要求为准。时间是优先级，不是质量保证；不能把“最近发布”直接称为“热门”。
- 只能核实相对日期时，如实写“页面显示 2 天前”等，不猜测精确日期。

### 平台和 Infron 视角

推荐应说明读者学到什么，以及它如何帮助理解模型选择、部署、工作负载或延迟、吞吐、成本、可靠性之间的取舍，而不是只说“与 AI infrastructure 相关”。

- **X**：围绕一个具体发现或工程 trade-off，给出简洁分享角度。
- **LinkedIn**：补充问题背景、必要机制和对开发者或团队的意义。
- 讨论角度不等于产品事实；Infron 的模型支持、价格、优惠和合作必须另用当前官方资料核实。默认只给简短角度；完整英文文案按用户要求提供。

## 两种工作模式

### 默认：内容发现与推荐

这是日常模式。AI 搜索并筛选多个候选，实际阅读核心正文、必要的引用/媒体和相关一手资料，然后给出少量高价值推荐。它关注技术价值、时效、品牌适配和信息增量，不是发布审批。对读不到核心内容或主张无法核实的候选应替换；品牌灰区按具体情况判断并说明重要限制。

### 明确触发：单帖发布前审核

只有用户明确要求“这条原帖能不能直接 repost/quote repost”“请做发布前审核”等，才进入严格审核。此模式会记录身份、核心主张、引用、媒体、链接、证据完整度、时间和去重结果，必要时输出 Hold、Reject 或未完成状态。用户只说“帮我找内容”时，不要把旧审核表格和 Hold 清单作为默认交付。

严格审核工具目前是离线、手工输入的 X 审核工具：脚本不联网、不替 AI 阅读页面，也不自动判断语义；LinkedIn 不能沿用 X-only 输入合同伪造审核通过。

## 项目结构

```text
README.md
Install-To-Project.ps1
skills/infron_repost_sourcing/
  SKILL.md             # 日常入口和审核模式
  agents/              # 界面调用提示
  references/          # 编辑规则、来源线索和旧审核合同
  assets/              # 旧审核配置和合成模板
  scripts/             # 旧审核工具及其测试
workflows/infron-content/
  02_Brand_Context.md  # 精简品牌上下文
```

旧版审核工具和配置保留以支持明确的审核任务；其中的 Model/Other 配额、时效和最多两条输出不代表当前默认推荐规则。`references/` 是按需读取的规则和合同，不是要求每次聊天全部读完的固定报告。详细历史试验、运行结果和真实状态不随此仓库分发，也不是完整的官号历史。缺少历史时不得声称已完成官号去重。

默认推荐仅将**有依据确认已经发布或转发**的内容作为严格历史去重依据；曾被推荐或接受不等于已发布。旧离线审核程序仍可能屏蔽曾推荐的项目，使用时要说明这一限制，不能把它的结果当作已发布证明。

## 安装到另一个项目

安装器不安装到全局位置，不上传或发布。若目标项目有更新的品牌上下文，应保留目标项目版本；Skill 只读取当前目标项目中的品牌上下文。

## 复用前的团队约定

- 用当前任务 brief 和最新官方资料覆盖通用规则；README 和 Skill 不能替代具体产品、价格、合作或可用性核验。
- 不把来源池当作作者白名单，也不把历史分享当作永久批准。
- 不把“读过帖子”写成“独立复现实验”；作者报告的性能数字要保留工作负载、硬件和测量条件。
- 不发布、不点赞、不私信、不购买、不部署、不创建定时任务。这个 Skill 的交付是推荐和判断，不是账号操作授权。
- 如果 X 或 LinkedIn 被登录、地区、媒体或安全限制阻断，说明具体缺口并更换候选；不要猜 URL、绕过限制或只凭搜索摘要放行。两类来源均在范围内时，可以推荐已读一手内容，但必须标明不是社媒原帖。

## 常见限制

- 没有独立的 X/LinkedIn API 采集器；发现和阅读依赖宿主 AI 的搜索/浏览工具。
- 访问权限、登录状态和媒体可读性会影响推荐数量；一次成功试跑不代表稳定召回率或 Mentor 认可率。
- 旧脚本的测试只验证输入合同、证据声明、去重和状态机，不验证网络搜索、网页阅读或推荐质量。
- 当前没有自动保存团队历史。只有用户明确提供已发布/已接受等反馈时，才应记录为事实。

## 维护与公开发布

离线工具的合成测试使用 Python 标准库，在项目根目录运行：

```powershell
python -m unittest discover -s skills\infron_repost_sourcing\scripts -p "test_*.py"
```

测试验证旧工具的声明校验和状态行为，不证明联网搜索、帖子阅读或推荐质量。运行数据建议放在被忽略的 `local/` 下，不要提交账号状态、审核结果、凭证或其他私有资料。

默认推荐流程的人工场景评估见 [sourcing-scenarios.md](skills/infron_repost_sourcing/references/sourcing-scenarios.md)。这些场景需要在新的 AI 上下文中实际执行和记录，不由上述 Python 测试自动验证。行为规则以 [SKILL.md](skills/infron_repost_sourcing/SKILL.md) 为准；调整行为时应同步更新本说明和场景。

公开上传前应自行审阅品牌规则、来源记录、当前变更和**全部 Git 历史**。从工作区移除旧资料或添加 `.gitignore` 不会清除已有提交；不要在未确认历史适合公开前推送现有历史。
