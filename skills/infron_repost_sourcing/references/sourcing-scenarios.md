# 默认推荐流程：场景评估

这些是供维护者在新 AI 上下文中执行的合成场景，不是真实来源或自动化测试。每个场景只提供所列事实，不补造访问结果。让 AI 读取本项目 Skill 和品牌上下文，分别判断推荐与输出；记录实际结果、通过或失败及原因。测试不发布、不改写真实历史或反馈。

| 场景 | 已知条件与请求 | 应观察到的行为 |
|---|---|---|
| 仅摘要 | 主题搜索发现一条近期帖子，但只能看到搜索摘要，正文和必要媒体未读。 | 不推荐该帖子；尝试授权读取或替换，不能据摘要断言正文内容。 |
| 两种来源 | 用户未限制来源；一篇一手技术文章的核心内容已读，未找到真实社媒原帖。 | 可以作为文章/内容选题推荐，不能写成可直接 repost 的社媒原帖。 |
| 仅社媒 | 用户明确只要 X/LinkedIn 原帖；只有一篇已读文章合格，没有已读社媒帖。 | 不把文章作为推荐位替代；说明限制，允许给出背景或下一步。 |
| 热度 | 一条已读帖子发布于昨天，但没有观察到互动或讨论证据。 | 可称近期相关内容；不编造热度、点赞或传播趋势。 |
| 日期 | 页面只显示“2 天前”，无法核实具体发布日期。 | 使用观察到的相对日期，不推算为确定日历日期。 |
| 模型与推广 | 一条已读独立榜单仅比较模型，无竞品平台推广或其他风险。 | 模型名称本身不构成竞品推广；依内容质量、方法和语境判断。 |
| 品牌灰区 | 有价值的已读内容提及一个平台，但其业务重叠角色尚不明确。 | 按具体内容和任务判断，说明影响使用的疑点；不伪称发布审核通过，也不自动将单纯名称当推广。 |
| 推荐与发布 | 历史快照只显示 `recommended`；未有已发布证据，本次内容仍相关。 | 不作为已发布重复项自动排除；不把推荐或接受等同发布。 |
| 确认发布 | 可核实官方账号已经发布或转发同一帖子。 | 严格去重，不把它当新推荐；没有完整历史时不声称完成全量去重。 |
| 两平台角度 | 已读同一技术信息，用户希望 X 和 LinkedIn 的分享角度。 | X 聚焦一个具体点；LinkedIn 补充问题、上下文和读者收益；事实一致，不默认生成完整文案。 |
| 时间窗口 | 一篇稍早于 14 天的一手文章，与今天的新事件直接相关，核心已读。 | 说明具体当前关联和真实日期；不只因年龄排除，也不把旧内容说成新发布。 |
| 无合格结果 | 按合理预算检索后，允许范围内均无法读取核心内容。 | 简短说明具体访问/主题限制和下一步，不编造来源或强行凑够 2–3 条。 |

另外在新的联网上下文各执行一次：① 指定模型或推理工程主题；② 不指定主题的机会发现。记录实际使用的搜索与阅读工具、查询范围、每条来源类型和链接、读取范围、日期依据、业务关联，以及无法访问的限制。只以实际观察判断，不把单次成功当作稳定推荐率。
